# 吾身工程项目基线

**文档状态：** 当前有效的工程事实来源

**最后更新：** 2026-09-28

## 当前有效基线

「吾身」是一个本地优先的 Web PWA。用户可以在浏览器中记录内容，原始记录由浏览器本地保存；只有用户主动选择内容并明确确认后，所选文本才会发送到无状态 AI 网关进行整理。AI 结果经过结构化解析、确定性来源校验和语义复核后，返回浏览器并由用户本地保存。

当前工程实现只使用以下技术路线：

- **前端：** React、TypeScript、Vite、Vite PWA 插件
- **本地数据：** Dexie/IndexedDB。浏览器本地数据是原始记录的权威副本
- **契约：** Zod、OpenAPI、`openapi-typescript`
- **后端：** FastAPI、Pydantic、HTTPX、uv
- **AI：** 通义千问 Qwen-Plus，通过 DashScope 调用结构化输出
- **验证：** Vitest、Pytest、Playwright

微信小程序、腾讯云开发等内容只保留在竞赛方案文档中作为产品说明或历史参考，不得作为代码实现依据。

## 产品目标与第一阶段范围

第一阶段要证明一条可运行的本地优先闭环：

1. 用户可以输入一段记录。
2. 系统原样保存记录，并在刷新后仍能读取。
3. 用户明确选择记录并确认后，系统才允许请求 AI 整理。
4. AI 网关返回符合约定结构的结果。
5. 结果中的结论可以回指原始记录；不能回指的内容不能进入最终结果。
6. 用户可以查看、导出和删除自己的本地数据。

第一阶段不要求一次完成全部趋势分析、长期记忆、商业化、账号体系或正式规模化部署。

## 架构与数据流

```text
用户输入
  -> React 页面
  -> Dexie/IndexedDB 保存原始记录
  -> 用户主动选择并确认
  -> FastAPI 无状态 AI 网关
  -> Qwen/DashScope 结构化生成
  -> 确定性来源校验与语义复核
  -> React 展示结果
  -> Dexie/IndexedDB 保存结果
```

记录模式与整理模式必须分开：

- **记录模式：** 原样保存，返回简短确认，不调用 LLM。
- **整理模式：** 仅由用户显式触发；发送被选择的内容，生成结构化结果，校验后保存。

FastAPI 网关不保存日记数据库，不拥有用户原始记录的长期副本，不承担账号同步或向量数据库职责。除非另有批准的决策记录，浏览器本地数据始终是权威副本。

## 技术栈与版本原则

- 依赖必须有明确用途，并在 Pull Request 中说明原因。
- 前后端共享的数据格式先写入 `docs/engineering/CONTRACTS.md`，再实现代码。
- Pydantic 模型负责后端输入输出校验，Zod 负责前端运行时校验。
- OpenAPI 由 FastAPI 接口生成，前端类型通过 `openapi-typescript` 同步。
- 测试数据必须是虚构或脱敏内容，不能使用真实日记。
- 密钥通过环境变量注入，不写入源代码、日志或提交记录。

## 明确不做的事情

以下事项不属于当前工程基线，除非新增并批准决策记录：

- 微信小程序前端
- 腾讯云开发作为当前实现平台
- 云端日记数据库或默认账号同步
- 用户未确认时把原始记录发送给 AI
- 记录期间主动分析、追问或生成总结
- 连续打卡、排行榜、勋章和制造断档压力的提示
- 让 AI 自行改变公共接口、技术栈或产品范围

## 术语表

| 术语 | 含义 |
|---|---|
| 本地优先 | 浏览器本地数据可独立使用；云端服务不是原始记录的唯一来源 |
| 原始记录 | 用户输入后未经 AI 改写的文本和必要元数据 |
| AI 网关 | 接收已获用户确认的文本、调用模型并返回结构化结果的 FastAPI 服务 |
| 结构化输出 | 符合约定 JSON Schema 的模型结果，而不是任意自然语言段落 |
| 来源证据 | 结果中能指向具体记录和原文片段的引用信息 |
| 契约 | 模块之间共同遵守的输入、输出、错误和版本规则 |
| 垂直切片 | 从用户入口到数据保存或展示都能独立运行和验收的一小段功能 |
