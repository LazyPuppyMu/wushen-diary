# 比赛版路线

路线只覆盖一条可演示主链路：

```text
浏览器本地写日记 -> 用户选择 -> 明确确认 -> AI 整理 -> 精确引用 -> 校验 -> 展示/导出
```

## 阶段 1：工程入口

**目标：** 让每个后续任务从同一份基线、Issue 和契约开始。

**完成证据：** `docs/engineering/` 文档存在，根目录入口可访问，`docs/api-contract.md` 被声明为唯一字段来源，现有测试通过。

## 阶段 2：前端主线

**目标：** 在不改变 API 字段的前提下完成本地日记到确认发送的浏览器流程。

**工作顺序：**

1. 保持 Dexie/IndexedDB 日记保存和刷新恢复。
2. 增加选择记录和发送前确认，明确展示数量、日期范围和字符数。
3. 只对已确认的选择调用 `/v1/organize`，处理 loading、`503`、网络错误和非法结果。
4. 展示七类结论、fact/inference、confidence 和引用定位。
5. 增加本地 Markdown 导出和清空全部数据，并验证移动端不横向溢出。

**完成证据：** 前端构建和测试通过；刷新、选择、取消确认、错误引用、含 emoji 的引用定位、导出和清空在浏览器中有可复现结果。

## 阶段 3：完整链路验收

**目标：** 用已配置的 provider 完成一次真实演示，并确认错误输入不会变成正常结论。

**完成证据：** 后端 pytest、前端测试和构建通过；真实 provider 请求只来自用户确认；错误 quote 被拒绝；没有密钥、真实日记或服务端持久化数据进入仓库。

## 明确不扩展

本路线不包含登录、云端日记数据库、向量库、多 Agent、推送、社交和长期运营功能。它们不属于 48 小时比赛演示版的验收范围。
