# 吾身 AI 工作手册

这份手册是给参与本项目的任何 AI 使用的执行协议。AI 必须把仓库中的规则、契约和测试结果当作工作依据，不能只依赖当前对话中的描述。

## 1. AI 的角色和权限

AI 是实现和分析助手，不是项目负责人。

AI 可以：

- 解释项目文件和技术选项
- 起草代码、测试、文档和 Issue
- 在当前任务范围内修改允许的文件
- 运行测试、启动检查和静态检查
- 报告变更、风险、假设和替代方案

AI 不可以：

- 自行决定产品范围、优先级或技术栈
- 在没有人批准时改变公共接口、数据格式或架构
- 把多个 Issue 合并成一个“顺便完成”的任务
- 直接修改或合并 `dev` 或 `main`
- 读取、打印、提交或传播 API 密钥和真实日记
- 没有测试证据就声称任务完成

## 2. 每次任务的读取顺序

开始任何任务前，按下面的顺序读取：

1. 根目录 `AGENTS.md`
2. `docs/engineering/PROJECT_BASELINE.md`
3. 本文件
4. 当前 GitHub Issue 的全文
5. 与任务相关的 `docs/engineering/CONTRACTS.md`
6. 与任务相关的 `docs/engineering/DECISIONS.md`
7. 将要修改的源文件和测试文件

如果这些内容互相矛盾，暂停编码，列出冲突的文件、具体段落和影响，等待人决定。

## 3. 开始实现前必须复述

在修改文件前，先输出以下内容：

```text
任务目标：我理解本任务要让什么行为成立。
明确不做：本任务不会实现哪些相关但未包含的内容。
输入与输出：当前模块从哪里取数据，要提供什么结果。
允许修改：我将修改哪些文件，不会修改哪些文件。
验收条件：我会用哪些可观察条件判断完成。
验证方式：我会运行哪些测试或启动检查。
风险与假设：哪些内容尚未被代码或测试验证。
```

如果无法完成这次复述，不得开始写代码。

## 4. 标准任务提示词

人类成员可以把下面模板填入 AI 对话。AI 收到后先复述，不要直接修改文件。

```text
请先阅读 AGENTS.md、PROJECT_BASELINE.md、AI_PLAYBOOK.md、当前 Issue 和相关契约。

任务目标：
明确不做：
当前契约：
允许修改的文件：
验收条件：
测试命令：
已知依赖：

请先复述你对目标、边界和验收条件的理解，再列出最小实现计划。
如果需要改变公共接口、技术栈、数据格式、依赖或其他 Issue 的范围，请先停止并说明原因。
```

## 5. 实现规则

- 先检查现有代码和测试，再决定新增或修改什么。
- 对行为变更先写或更新测试，再写最小实现。
- 只修改当前 Issue 允许的文件，不做无关格式化和重命名。
- 新增公共字段、端点或错误码前，先更新 `CONTRACTS.md` 并说明兼容影响。
- 前端输入和后端返回都要做运行时校验；不能把模型返回的任意文本直接当作可信数据。
- AI 调用必须有超时、错误处理和不丢失原始记录的路径。
- 记录模式不得调用 LLM；整理模式必须有用户显式选择和确认。
- 测试只能使用虚构或脱敏内容。

## 6. 必须停止并请求人决定的情况

遇到以下任一情况，停止修改文件，报告证据和影响：

- 需要改变 React PWA、FastAPI、Qwen/DashScope 的技术基线
- 需要改变目录结构或已有公共接口
- 需要修改另一个 Issue 的范围
- 需要删除、迁移或批量重写用户数据
- 需要新增依赖、访问密钥或外部服务权限
- 测试失败且原因不明确
- 发现文档、契约和实现互相冲突
- 无法确定某个行为的验收标准

停下时不要用猜测填补缺失信息，也不要先提交一个“临时方案”绕过边界。

## 7. 完成前检查

在报告任务完成前，依次检查：

1. 当前分支是功能分支，不是 `dev` 或 `main`
2. `git diff` 只包含当前 Issue 的改动
3. 没有密钥、真实日记和临时文件
4. 契约和实现的字段、类型、错误码一致
5. 任务要求的单元测试、接口测试或端到端测试已运行
6. 原始记录在 AI 失败、超时或返回无效结构时不会丢失
7. 结果中无法回指原文的结论不会被保存为有效结论
8. 文档和测试命令已经同步更新

## 8. 统一完成报告

每次任务结束时，按下面格式报告：

```text
完成摘要：

修改文件：
- path/to/file

验收条件：
- [x] 条件一：证据是什么
- [x] 条件二：证据是什么

运行的命令和结果：
- `command`: PASS/FAIL

契约或文档变化：
- 没有 / 具体变化

未验证的假设：
- 没有 / 具体内容

已知风险：
- 没有 / 具体内容

回滚方式：
- 回退到哪个 commit、标签或分支
```

如果任何验收条件未完成，必须明确标记为未完成，不能用“基本完成”代替。

## 9. 安全边界

- 从环境变量读取密钥，但不要在终端输出、测试快照或报告中显示密钥值。
- 使用 `.env.example` 说明变量名和格式，不提交真实 `.env`。
- 不把真实用户记录复制到 Issue、PR、日志或测试文件。
- 调试输出在提交前删除或替换为脱敏样例。
- 不下载或引入来源不明的依赖。
