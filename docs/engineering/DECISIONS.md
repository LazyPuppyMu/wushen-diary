## ADR-0001：采用 React PWA + FastAPI + Qwen/DashScope

- 状态：已批准
- 日期：2026-09-28
- 决策人：项目团队
- 影响范围：全部工程实现

### 背景

项目需要一个浏览器可访问、支持本地优先记录和主动 AI 整理的实现方案。此前竞赛提交版文档写过微信小程序和腾讯云开发，另一份实施方案写过 React PWA 和 FastAPI，存在实现依据冲突。

### 选项

1. React PWA + FastAPI + Qwen/DashScope
2. 微信小程序 + 腾讯云开发
3. 其他前端和后端组合

### 决定

工程实现统一采用 React PWA + FastAPI + Qwen/DashScope。浏览器通过 Dexie/IndexedDB 保存本地权威记录；FastAPI 作为无状态 AI 网关；Qwen 只在用户明确选择并确认后处理选中内容。

### 影响

- 竞赛提交版中的微信小程序和腾讯云开发段落不直接指导代码。
- 前后端需要共享 OpenAPI、Zod 和 Pydantic 契约。
- 需要设计真实 API 不可用时的假网关和错误路径。

### 后续检查

- 阶段 0 验证三个人能运行同一套前端和后端。
- 阶段 2 先使用假网关验证契约，再接入 DashScope。

## ADR-0002：浏览器本地数据是原始记录权威副本

- 状态：已批准
- 日期：2026-09-28
- 决策人：项目团队
- 影响范围：数据层、隐私、导出和删除

### 背景

产品强调本地优先和数据主权，记录期也不应依赖云端服务才能保存原文。

### 选项

1. 云端数据库作为唯一副本
2. 浏览器本地作为原始记录权威副本，网关只处理用户确认的内容
3. 浏览器与云端双写并默认同步

### 决定

采用第 2 项。原始记录写入 IndexedDB；用户主动选择并确认后，所选内容才进入 AI 网关；AI 结果返回后也保存到本地。除非之后新增决策记录，不建设云端日记数据库、账号同步或默认向量库。

### 影响

- API 失败不能导致原始记录丢失。
- 导出和删除必须覆盖本地数据。
- 跨设备同步不属于当前基线。

### 后续检查

- 阶段 1 测试刷新后读取、删除和异常保护。
- 阶段 5 验证离线记录和导出文件。

## ADR-0003：记录模式不调用 LLM，整理模式需要显式确认

- 状态：已批准
- 日期：2026-09-28
- 决策人：项目团队
- 影响范围：交互、隐私、AI 网关

### 背景

产品要避免用户在记录时被 AI 的总结和追问影响表达，同时避免未确认内容被发送到外部模型服务。

### 决定

记录模式只原样保存并返回简短确认，不调用 LLM。整理模式必须由用户主动触发、选择参与记录并明确确认后才发送请求。`POST /v1/organize` 请求必须包含 `consent: true`；缺失或为 `false` 时由 API 拒绝。

### 影响

- 该边界由应用交互和请求字段共同保证，不能只依赖提示词。
- `consent` 仅声明用户对本次请求的确认，不记录确认时间，也不能替代前端确认交互。
- 记录模式和整理模式必须分别测试。
- 所有整理请求都需要可追溯的 `consent` 字段。

### 后续检查

- 阶段 1 证明记录无需网络也能保存。
- 阶段 3 验证未确认内容不会出端。

## 新决策的进入条件

以下事项在实现对应阶段前必须新增 ADR，并明确负责人和验收方式：

- 本地记录的具体索引、迁移和冲突处理方式
- 选中内容如何在浏览器中确认并发送
- 真实 DashScope 请求的认证、超时和重试策略
- 来源证据的偏移量定义和多字节文本处理方式
- 演示环境与正式部署环境
