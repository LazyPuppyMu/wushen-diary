# 3 分钟比赛演示脚本

演示前确认前端和已配置的整理服务正在运行，浏览器使用全新的演示数据库。只展示现场产生的真实返回；服务不可用时展示明确错误，不用 mock 或占位结果替代。

## 0:00–0:25 写日记

1. 打开记录页面。
2. 输入一条虚构演示记录，例如：“今天把演示环境跑通了，感谢小组帮我检查配置，明天想先练十分钟讲解。”
3. 点击保存，展示记录原文和保存成功状态。
4. 强调此时只是记录，页面没有请求整理服务。

## 0:25–0:45 刷新并确认本地保存

1. 刷新浏览器。
2. 展示刚才的原文仍在列表中。
3. 说明原始记录来自浏览器 IndexedDB，刷新不依赖 AI 服务。

## 0:45–1:10 选择并确认发送

1. 勾选这条记录，打开整理面板。
2. 展示未选择时不能发送；选择后点击“确认发送”。
3. 在确认动作前指出只有选中的内容会进入本次请求。
4. 等待真实整理响应；不要在等待期间显示预先写好的结果。

## 1:10–1:45 查看分类和证据

1. 展示返回的 `fulfillment`、`gratitude`、`improvement` 等分类。
2. 指出计划被整理为“记录了计划”，没有被写成已经完成。
3. 点击一条结论的引用，跳回原始记录中对应的精确 quote。
4. 说明引用位置由服务端根据原文计算，模型不能自行填写 `start/end`。

## 1:45–2:05 演示错误引用被拒绝

1. 在开发演示入口或测试面板提交一个不存在的 quote，或把 `entry_id` 改成未提交的值。
2. 展示校验错误，例如“quote was not found”或“entry_id was not submitted”。
3. 确认错误结果没有进入正常结果列表，原始日记仍然保持不变。

## 2:05–2:35 导出

1. 点击导出。
2. 打开导出的本地文件，展示原始记录和已保存的整理结果。
3. 强调导出来自浏览器本地数据，不是从服务端日记数据库读取。

## 2:35–3:00 清空

1. 点击清空入口并确认。
2. 展示记录和本地整理结果从列表中消失。
3. 最后说明：记录默认留在浏览器；只有用户选择并确认后才发送整理请求；错误引用不能进入正常结果。
