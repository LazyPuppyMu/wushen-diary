# 3 分钟比赛演示脚本

关联任务：[Issue #11](https://github.com/LazyPuppyMu/wushen-diary/issues/11)。本脚本在 PR #10 合并后执行；准备完成不代表真实 AI 链路已经验收。

演示前按 [完整链路验收清单](stage3-acceptance.md) 检查服务和浏览器。使用单独的浏览器演示配置文件，只写入 [虚构演示记录](../eval/demo-entries.json)，不清空已有个人日记。真实 Qwen 响应只在用户选择并确认后请求；服务不可用时展示错误。

提前打开后端终端，并在 `apps/api/` 运行一次下面的错误引用测试，确认环境可用。正式演示时再次运行；这里使用 FakeClient 注入错误模型输出，没有调用 Qwen。

```powershell
uv run --cache-dir ..\.uv-cache pytest -q tests/test_organize.py::test_organize_rejects_invalid_quote tests/test_evidence_validator.py::test_validate_evidence_rejects_entry_id_that_is_not_submitted
```

## 0:00–0:25 写日记

1. 打开记录页面。
2. 输入 `demo-mixed` 的日期和原文：“今天完成了演示提纲，很有成就感。感谢同伴帮我检查配置；明天打算练十分钟讲解，但还没开始。”
3. 点击保存，展示记录原文和保存成功状态。
4. 强调此时只是记录，页面没有请求整理服务。

## 0:25–0:45 刷新并确认本地保存

1. 刷新浏览器。
2. 展示刚才的原文仍在列表中。
3. 说明原始记录来自浏览器 IndexedDB，刷新不依赖 AI 服务。

## 0:45–1:10 选择并确认发送

1. 展示未选择时“整理所选”不可用，再勾选这条记录。
2. 点击“整理所选”，展示确认框中的条数、日期范围、字符数和发送说明。
3. 先取消一次，展示没有整理请求；再次点击“整理所选”，确认发送。
4. 等待现场的真实整理响应。响应慢时缩短讲解，超出三分钟就如实记录演练超时；失败时展示错误和仍在本地的日记。

## 1:10–1:45 查看分类和证据

1. 展示实际返回的分类、事实/推断和置信度，不预先承诺固定措辞、数量或七类齐全。
2. 检查计划保持“打算/尚未开始”语义，没有被写成已经练完讲解；现场不符合时明确指出评测失败。
3. 点击一条结论的引用，跳回原始记录中对应的精确 quote。
4. 说明引用位置由服务端根据原文计算，模型不能自行填写 `start/end`。

## 1:45–2:05 演示错误引用被拒绝

1. 切到后端终端，运行演示前准备的两个 pytest。
2. 说明测试主动注入了不存在的 quote 和未提交的 `entry_id`；它们是测试数据，不是现场 Qwen 返回。
3. 展示 `2 passed`：路由测试断言错误 quote 返回 `502`，校验器测试断言错误 `entry_id` 被拒绝。详细校验原因留在测试断言中；API 返回通用错误，不泄露日记内容。
4. 切回页面，展示刚才的原始日记未被这些测试修改。页面没有专门的错误注入入口。

## 2:05–2:35 导出

1. 点击导出。
2. 打开 `wushen-diary-日期.md`，展示日期和原始日记。
3. 说明当前 Markdown 导出只包含 IndexedDB 日记；整理结果只展示在当前页面，刷新后不会恢复，也不包含在导出文件中。
4. 强调导出在本机生成，没有上传文件。

## 2:35–3:00 清空

1. 在专用演示浏览器中点击“清空”，展示确认框；明确只清空这些虚构演示记录后再确认。
2. 展示日记列表和当前页面整理结果清空，刷新后仍无日记。
3. 最后说明：记录默认留在浏览器；只有用户选择并确认后才发送整理请求；错误引用不能进入正常结果。

## 服务不可用时

缺少 key 时应显示 `503`，网络失败时应显示连接错误，日记仍可刷新恢复和导出。可以完成本地流程演示及错误引用测试，但必须报告“真实 AI 整理未通过/未验证”，不能将已有结果或测试注入输出当作本次成功返回。
